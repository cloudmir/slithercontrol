## 1. 높은 우선순위: 부스트 유지가 새로운 공격의 가속 요청을 막는다

코드: `pilot.py:641–647`. `CONFIRM`은 공격 시 우회하지만 `BOOST_DWELL`은 `attacker`가 있어도 적용된다. `mode == emergency` 분기만 이 규칙을 통과하지 않는다. **공격받는 evade와 안전 후보가 전혀 없는 emergency는 다르다.**

동일한 합성 관측·동일한 내부 상태에서 `BOOST_DWELL`만 바꾸는 반례:

1. safe 프로필, 이전 부스트가 켜져 있던 상태에서 평온한 관측을 두 번 받아 t=0.95에 끈다.
2. t=1.00에 (100,350) 위치에서 아래쪽으로 향하는 머리(sp=6, sc=1.5)가 나타난다.
3. 현재 코드: 회피 방향 -90°, **부스트 꺼짐**, 예측 최소 여유 23.7px.
4. 유지 제한만 해제: 같은 회피 방향 -90°, **부스트 켜짐**.

두 경로 모두 현 안전 기준을 통과하므로 제한이 회피용 가속을 억제한다. ‘한번 껐다가 0.28초 이내에 다시 켜지 않음’은 잡음뿐 아니라 새로 발생한 공격에도 적용된다. 이것은 합성 판단 반례이며 실제 사망을 재현했다는 뜻은 아니다. 부스트 경로의 큰 여유 출력은 예측 범위·거리 제한의 영향을 받으므로 실제 2만 px 안전 여유로 해석하지 않는다.

공격형 P18 입력 재생에서도 dwell이 최종 부스트 선택을 바꾼 390틱 중 **252틱은 공격을 인식한 상태에서 켜려던 부스트를 끈 채 유지**한 경우다. 연속 틱을 포함하며 252개의 독립 공격이나 회피 실패를 뜻하지 않는다. 예: 170651판 t=354.282, 켜려던 경로 최소 여유 45.9px→유지된 순항 경로 41.6px. 반대로 t=354.780에서는 20.7px→81.2px로 순항 쪽 여유가 더 크다. 그러므로 공격이면 무조건 부스트를 켜는 수정도 적절하지 않다. 실제 통과 시간·회전 반경·최소 여유를 비교해야 한다.

개선: 평온한 채집 중의 불필요한 전환과 새 위협에 대한 가속·감속을 구분한다. 공격 시작, 출구가 닫히는 시각, 두 속도 경로의 위험 차이가 명확한 경우에는 유지 제한보다 회피 기동을 우선한다. 실제 속도 `sp`, 아직 반영되지 않은 입력, 부스트 소모까지 평가한다. `RAMP/2`는 휴리스틱이며 최적 유지 시간의 실측 근거가 아니다. 0.57초보다 짧은 가속도 유효한 이동량을 만들 수 있다.

## 2. 포위 탈출의 목표 충돌은 일부 남아 있다

## 4. why와 page_ms는 원인 진단에 아직 불충분하다

- `why`는 몸/벽과 머리의 최소 여유다. `safe`에는 후속 경로, 회전 방향 제한, 틈별 안전 여유도 반영된다. 여유가 모두 양수여도 거절될 수 있다. 이 5개 값만으로 ‘왜 버렸는지 바로 센다’는 설명은 과도하다.
- coil의 `hard`는 지속 최대 회전 경로로 계산하지만 `why`는 일반 목표 방향 후보의 여유다(`pilot.py:607–612,690–698`). 서로 다른 경로의 수치를 원인 분석에 섞으면 안 된다.
- `page_ms` 시작점은 세그먼트·먹이·자기 몸 배열 수집 **후**다. 종료점은 페이지 입력 변수와 가속 입력을 쓴 직후이며, 게임 패킷 전송·서버 적용·실제 회전 시작 시각이 아니다(`run_live.py:41–76`).

개선: 최종 출력 계획 ID/경로 종류, 선택 전후 후보 ID, 각 필터의 탈락 이유, confirm/dwell 개입 여부를 남긴다. 관측 시작·완료·페이지 입력 작성 시각을 나눈다. 명령 ID를 붙여도 서버가 실제로 적용한 명령 번호를 관측한 것으로 간주해서는 안 된다.

재생에서는 coil 경로의 최소 여유와 일반 후보의 몸/머리 최소 여유가 0.2px 넘게 다른 틱을 106개 확인했다. 문서에 설명한 why의 의미를 코일에도 그대로 적용해서는 안 된다.

## 6. 검증을 게임 움직임에 연결하는 순서

1. **출력 안정화의 부작용부터 검사:** 부스트를 끈 직후 새 머리가 옆에서 끼어들기, 급회전 중 감속 필요, 잠깐의 비상 진입 후 목표 변경. 지표는 명령 변경 횟수 외에 첫 회피 명령 시각·접촉 여부·최소 여유·출구 통과 여부.
2. **포위:** 출구 쪽에 먹이가 없는 경우, 먹이와 출구가 반대인 경우, 여러 머리의 가로막기 가점이 생기는 경우. 탈출 시간·닫히기 전 통과·재포위 여부를 비교한다.
3. **정밀 통로:** 폭이 다른 통로에서 실제 가속·감속·명령 지연을 반영한다. 입력 명령의 안정성만으로 통과 성공을 대체하지 않는다.
4. **코일:** 전진 속도·크기 변화와 상대 몸의 이동을 반영한 반복 궤적 오차를 잰다. 한 방향 회전 유지 자체를 같은 원의 정밀 추종으로 간주하지 않는다.
5. 조향 확인, 부스트 유지, 포위 가점 차단을 각각 켜고 끈 비교를 같은 장면에서 수행한다. 여러 변경의 합산 효과를 특정 규칙의 효과로 단정하지 않는다. 개발 장면과 평가 장면은 사건 단위로 분리한다.
