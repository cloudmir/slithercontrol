# 2.a 지연 측정 · 2.b 브라우저 플러그인 불필요 판정 (2026-09-25)

측정: run_live.py stage_ms, pilot 실서버 6판(runs/live_20260925_110338~111731). 단위 ms, p50/p95.

| 구간 | p50 | p95 |
|---|---|---|
| 관측(page.evaluate + 전송) | 5~6 | 13~18 |
| 판단(pilot) | 11~18 | 19~23 |
| 관측 시작→명령 전송 완료 | 22~33 | 41~52 |

- 제어 주기는 30Hz다. 게임 클라이언트도 방향을 마지막 전송 후 33ms가 지나야 다시 보낸다(research/game.js).
- 페이지 안 판단(플러그인·주입 JS)으로 줄일 수 있는 것은 관측·명령 전송 몫(p50 약 10ms, p95 약 25ms)뿐이다. 판단 계산은 그대로 남고, JS로 옮기면 거리장(OpenCV) 없이 오히려 느려질 수 있다.

판정: 2.b(플러그인)는 지금 필요 없다. 다음 조건이면 다시 본다.
- 실서버 사망 분석에서 반응 지연이 원인인 사례가 반복된다. 즉, 위협이 보인 뒤 0.1초 안에 죽는다.
- 관측→명령 p95가 60ms를 넘는다.

적용한 단축(2.a):
- pilot의 몸 거리 계산을 2px 격자 거리장으로 바꿨다. 붐비는 화면에서 141ms → 20ms.
- 먹이·머리 거리를 제곱거리로 계산한다.
