# V4 아키텍처 재설계 (사용자 "땜빵 금지, 한번 더 고려" 2026-09-30) — 코드 미착수

원칙: 기존 v4Step을 고치지 않고 새로 짠다. 모든 층이 같은 물리 모델(속도·가속·회전율·명령 지연)과 같은 시간 기준(관측 시각 t0=0)을 공유한다. 각 층은 입력·출력·불변식·계산 시간 상한이 정해진 독립 모듈이며 단위 검사를 가진다.

## 층 구조
| 층 | 주기 | 계산 시간 목표 | 입력 → 출력 |
|---|---|---|---|
| A 세계 모델 | 관측마다(30Hz) | ≤2ms | 관측 → 고정 격자 지도(몸·벽 여유, 관측 시각·만료), 적 머리 목록(위치·방향·속도·회전율) |
| B 적 도달장 | A 갱신마다 | ≤3ms | 1300px 안 머리 → 칸별 최조 도달 시각 T_e(칸) (회전 시간 + 가속 물리, 전 방향, 뒤쪽도 회전 시간만큼 늦게 도달) |
| C 길 찾기(느린 층) | 0.3~0.5초마다 또는 지도가 크게 바뀔 때, 비동기 | ≤40ms, 초과 시 중단하고 부분 결과 사용 | 상태(위치·방향·속도) 격자 A*, 회전 원호 전개, 라벨 2개(최소 비용·최소 시각) → 세계 좌표 경로(시각 붙음) + 계산 시작 관측 시각 |
| D 근접 회피(빠른 층) | 매 틱 | ≤2ms | 현재 관측 + C 경로 → 0.9초 후보 원호(직진·좌우 반/최대·부스트 유무, 현재 속도에서 가속) 검사 → 명령(방향·부스트) |
| E 추종 | 게임 루프마다 | ≤0.2ms | D 명령을 지연 보상해 마우스 각도로 (기존 추종층) |

## 불변식
1. D는 C 경로가 낡았으면(관측 시각 차 > 0.5초) 무시하고 단독으로 판단한다. C가 없어도 D만으로 동작한다.
2. D 후보 중 몸·벽 실제 접촉(간격<0)이 있는 후보는 절대 선택하지 않는다. 적 도달(T_e)은 위반 크기로 감점하되 절대 금지는 아니다 → 모든 후보가 막혀도 "가장 덜 나쁜" 원호를 낸다(v4none 제거).
3. 우리 속도는 상태다: 순항/부스트 이진이 아니라 현재 속도에서 가속·감속(0.57초 램프)해 시간을 계산한다(C·D 공통).
4. 방향 해상도는 큰 몸 부스트 회전(원호당 24°)이 표현되게 15°(24방향). 회전 불가(kmax=0)가 생기지 않도록 원호 길이를 회전율에 맞춰 조정한다.
5. 계산 시간은 관측 시각 기준으로 보상한다: C 결과에 계산 시작 시각을 붙이고, D는 (지금−그 시각)만큼 경로를 앞당겨 읽는다.
6. 목표는 세계 좌표. 교체는 (a) 목표 불가능 (b) 새 목표가 비용 15% 이상 낮음 (c) 목표 도달, 셋 중 하나일 때만.

## 검증(구현 전 정의)
- 단위: 원호 기하(끝점·반경), 도달장(정면·측면·후면 표본값), 가속 모델(0.57초 뒤 434px/s), 라벨 지배 규칙.
- 재생: 기록된 사망 21판 + 오늘 V4 사망 판에서 D 단독 / C+D 생존율과 계산 시간(전 프레임, p50/p95/최대).
- 실게임: 사용자 직접. 판정 지표는 사망 전 1초의 모드·명령 요동·계산 시간.

상태: 설계안. 사용자 확정 후 Codex 설계 검토 → "수정" 지시 후 구현.

## 추가 계약 (사용자 확정 2026-09-30, Codex 설계 검토 claim-v4-architecture-review-20260930 반영)
7. C는 별도 Worker에서 A/B의 불변 스냅샷과 지도 버전 번호를 읽는다. 완료 시 버전이 바뀌었거나 경로 주변 점유가 바뀌었으면 결과를 폐기한다(나이 기준만으로 채택하지 않음).
8. C가 40ms를 넘기면 충돌 검사가 끝난 경로 접두부만 반환한다. 인증된 접두부가 없으면 D 단독.
9. 상태당 라벨은 (도달 시각, 선호 비용, 최소 여유)의 비지배 라벨 최대 3~4개(bounded Pareto).
10. D 선택은 사전식: 몸·벽 비접촉 → 적 도달 위반 0 → C 경로 추종 → 성장. 위반 후보는 전부 위반일 때만 최소 위반으로.
11. A의 몸 기억은 지렁이 ID·선분 갱신·꼬리 소멸을 추적해 중복·허위 벽을 막는다. D는 매 틱 C 경로의 가까운 구간을 현재 관측으로 재검사.
12. C 목적함수 우선순위: 생존 가능 출구·시간 여유 1순위, 먹이 2순위. E 입력은 D가 검증한 짧은 시각표시 원호.
상태: 설계 확정(1~12). 구현은 사용자 "수정" 지시 후.

## 구현 1차 (2026-09-30, 빌드는 아래 표기) — 사용자 "수정하라"
- ext/pilot.js: v4World(A: 뱀 ID별 폴리라인 기억·만료, 고정 격자 여유), v4Reach(B: 회전 시간+가속 물리, 전 방향), v4Route(C: (셀,방향,부스트) 상태격자·실제 원호·비지배 라벨 3개·40ms 예산·부분 결과 반환·버전), v4Step(D: 0.9초 후보 원호 5회전×2부스트, 연속 속도, 사전식 선택: 접촉 금지→적 도달 위반 0→경로 추종→성장; 경로는 나이·근접 구간 재검사 후 사용), 추종층 E는 기존.
- ext/mod.js: 두 번째 Worker(worker2)에 'plan' 스냅샷을 V4_PLAN_MS(350ms)마다 전송, 버전 붙은 경로를 step 관측에 첨부.
- 오프라인(기록 4판, 두 층 동시 재생): 근접 회피 p50 0.2~0.6ms·p95 0.6~1.1ms·최대 9ms; 경로 탐색 p50 0.7~40ms·p95 7.6~41ms(예산 40ms에서 부분 결과); 명령 요동 5~29/1700프레임; 경로 사용률 96~99%.
- 미구현·차이: 라벨 3개(4 아님), C 조기 종료 없음(예산까지 탐색), 몸 기억은 뱀 ID 단위 교체(꼬리 소멸 추적은 관측 폴리라인 교체로 대체).
