# V3 합의 설계 — 위협 조건부 가용 경로 계획기 (Claude + Codex 협의, 2026-09-29 저녁)

사용자: "너와 codex와 협의해서 궁극적인 알고리즘을 만들어봐 … 땜빵 버그식 수정은 절대 안 됨 … 솔루션을 제대로 codex와 같이 도출 후 보고해."

협의 경과: Claude 초안(지연 반응 추격-회피 게임 계획기: 시간 점유 + τ_e 지연 도달 집합 + 후퇴 집합 불변식 + 기대 가치 목적 + 부스트=제어 변수 + 데이터 보정) → Codex 1차 비판(τ_e 상수 금지, 45° 잎 수는 후퇴로가 아님, 0.9초 탐색으로 5초 생존 선언 불가, 사망 확률 모델은 보조, "머리 뒤쪽 선회"는 규칙이 아니라 결과; **시간 기준 버그** 발견: research/v2_occ.mjs 절대시각 vs v2_route.mjs 상대시각 → 새 몸 무시, 재생 7/7 무효) → Claude 추가 제안 4건(커밋 관측, 자기 몸 방패, 관측 경계 900px 인증, 공격 정책 3종+출구 선점 검증) → Codex 2차 전부 찬성(조건 부가) + 최종 합의 표.

버그 수정: v2_occ.mjs 시간을 현재 틱=0 상대시각으로 통일(합성 반례: 새 몸이 놓이기 전 통과·놓인 뒤 차단 확인), 재측정: 6판 스모크 edgeEscape 재생 7/7(core 점유; core는 직진 0.5초만이라 새 몸 영향 작음), 감김 판 unknown, 닫힌 판 noPath.

## 최종 합의 설계(Codex 원문)
| 구성요소 | 합의 내용 |
|---|---|
| 시간·점유 | 매 계획에서 현재를 t=0으로 통일하고, 기존 몸과 새로 생성되는 몸을 같은 상대시각에 평가 |
| 상대 시나리오 | τ_e∈{0, 0.15, 0.30}; 가까운 부스트·조준 공격자와 커밋 관측 상대는 최악값, 나머지는 CVaR |
| 출구 평가 | 연결된 통로별 독립 출구 수, 통과 가능한 폭 여유, 상대보다 먼저 도착할 시간 여유 |
| 경로 탐색 | 0.9초 정밀 탐색: 3개 제어 × 10단계, 지배 가지치기, 빔 폭 10→40→160; 상위 12개에 5초 거친 출구 검사 |
| 실행·평가 | 25ms 예산을 단계별로 배분하고 초과하면 직전에 검증한 안전 명령 유지. 사망 확률은 보조 점수로만, 판·사건 단위 분리 평가 |

추가 합의(Claude 제안, Codex 조건부 찬성): 커밋 관측(부스트 시작+우리 쪽 조향 → τ_e=0 최악 승격, 해제는 히스테리시스; 가까운 부스트 상대는 커밋 전에도 최악값), 자기 몸 방패(우리 몸과 확실히 먼저 충돌하는 상대 경로만 제거, 방패 의존 출구엔 추가 여유), 관측 경계(1150px 밖 미인증, 출구 인증은 충돌 캡슐 전체가 900px 안일 때만), 검증 세트(v2_cutter 리드 0.3/0.5/0.8초 + 출구 선점).

| 단계 | 구현·합격 기준 |
|---|---|
| 0 | 상대시각 점유 수정과 물리·지연 계측. 새 몸 충돌 반례가 재현 후 해소되고, 실제 반환 명령과 검사 명령이 일치 |
| 1 | 시나리오, 커밋 관측, 자기 몸 충돌 판정. 확실하지 않은 상대 경로가 제거되지 않는 경계 사례 통과 |
| 2 | 독립 공격 검증. v2_cutter 리드 3종과 출구 선점에서 동일 조건 기존안 대비 방어 실패가 늘지 않으며, 실패 사건별 원인 기록 |
| 3 | 0.9초 정밀 탐색. 충돌·회전·부스트 제약을 만족하고 가지치기가 안전 후보를 잘못 제거하지 않음 |
| 4 | 연결 통로 출구와 5초 검사. 폭·시간 여유를 계산하고 900px 밖 경로를 인증하지 않음 |
| 5 | 온라인 통합. 매 틱 25ms 마감 또는 검증된 명령 유지가 작동하며, 판·사건 단위 생존과 활동 지표를 기존안과 동일 조건에서 비교 |

물리 한계(Codex): 순항 181~243px/s·부스트 437.5px/s; 90° 회전 최소 0.38→2.47초(sc 1→6); 부스트 0.9초 394px·5초 2188px → 1150px 관측 반경으로 5초 경로 전체 인증 불가. "절대 안 죽음"은 보증 불가, 실행 가능 목표 = 막힐 통로에 더 일찍 들어가지 않기·끊기 노출 시간 감소·선점 가능한 사체에 더 빨리 도착.

상태: 설계 합의, 구현 전. 단계 0의 시간 기준 수정은 완료.
