1. 명령 변경 → 서버 목표각(slither.wang) 일치 지연 중앙값 160~190ms, p95 220~350ms(패킷 송신 → wang 일치 190ms; 우리 쪽 변경 → 패킷 송신 17ms). 종전 가정 0.1초는 틀림. 망/서버 몫 분리는 미측정(TCP RTT 측정은 세션 종료로 미완).
2. 추종 정밀도(방향 추종): +0.25초 위치 오차 p50 3.9~5.2px, +0.5초 6~9px, 방향 오차 p50 1.7~1.9°, 명령 요동 0.2~0.7%. 순수 추종 0.13초는 방향 오차 17~29°로 실패(지연보다 짧은 선행).
3. 게임 클라이언트: 각도 패킷 33ms 초과 간격·251단계, 부스트 50ms 초과, 자기 wang은 서버 패킷으로 갱신.
4. 어제 V3 사망 4판(1·3·4·5)은 3초 전부터 다시 몰면 V2·V3 모두 생존 → 판단 오류(컨트롤 미스)였음. 3판만 명령 요동이 직접 원인, 나머지는 위험을 늦게 본 계획기 문제.
5. V3 오프라인(21판 재생·절단 시뮬 84 시나리오×3 리드): 최종 18/21, 57/57/56 vs V2 17/21, 49/55/56 — 동급. 실게임은 V1보다 짧음.

## 4. 결론·판단
- V2/V3는 V1의 검증된 방어(공격 가드·감김·통로)를 끄고 대체하는 구조라 "강화"가 아니라 "교체"였고, 아직 V1(70판 통계)에 못 미친다. V1은 경험적 가중치 계획기이지만 운은 아니다.
- 추종층은 정밀도 검증 완료, 생존 효과 미검증.
- 사용자 지적(사실로 기록): "대충대충, 죽으면 버그 패치하듯". 인정한 항목: 지연 미측정 설계, V3_RISKW 누락, 추종 로그 오류로 1판 폐기, 하루 3번 위협 모델 교체.
