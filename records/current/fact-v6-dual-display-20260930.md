# V6 미로·근접 경로 분리 표시와 탐색 범위 확대

사용자: “두개 알고리즘 (미로, 근접)을 별도로 앞에 표시해줘 그리고 미로는 좀더 길게는 못하나?”

빌드0930-984f4809. ext/pilot.js SHA-256 117abee975a007eef7161c49c49227c5e9bd9a2161cf1f93bdf7f7579e4bd9e2, ext/mod.js 14e171576445e38610c16658d4fb5d992aa685d9532d8bd0571fee5ee5d6b5d6, params.json 588a7517795d93e38941c5f187d2ba2dc671aea6f88369e3b368c37b277cb68b. 직전 원본은 research/v6_display_before_20260930/ 보존.

구현:
- 미로 점선(출구 경로 녹색, 부분 경로 주황색)과 근접 경로 실선(청록, 모든 후보 충돌 예상 시 빨강)을 동시에 표시. 머리 옆에 각각 이름과 상태를 표시한다. 표시 탭에서 각각 켜기/끄기 가능. 거부되거나 낡은 미로 경로를 계속 표시하지 않는다.
- 미로 목표700→1000px, 탐색시간6→8초, 지도·관측 반경1150→1400px. 홈에서 목표 거리·탐색 시간을 바로 조절할 수 있다. 범위를 늘려도 적 도달 위험으로 막힌 부분 경로를 임의 연장하지 않는다.
- 기존 저장 설정에 새 표시 항목이 기본값으로 합쳐지도록 normalize의 병합 순서를 수정했다.

확인:
- 구문 검사 통과. 합성 열린 공간1019px 출구 경로 및 두 몸 사이 통로 통과. 낡은 미로선 제거 후 근접선 유지 검사 통과.
- 직전 실게임 마지막60초1642프레임 오프라인 재생: 거시 p95 6.53ms, 근접 p95 2.7ms. 해당 사망 구간에서는 부분 경로만 확보했으며 길어진 출구 경로 성공으로 주장하지 않는다.
- 실제 Worker를 쓰는 모의 브라우저에서 두 경로 이름·렌더링·개별 토글·기존 설정 병합 확인, 오류0. research/v6_display_mock_20260930/result.json 및 dual_paths.png. 재생 결과 research/v6_display_verify_20260930.json.
- Windows 대기 중 탭에서 확장 재로드 후 빌드 일치, V6 활성화와 확대값 적용 확인(windows_applied.json). 봇OFF·게임OFF. 새 판 실행 없음.

직전 사망의 선택·추종 문제와 먹이 추구는 이번 표시 변경으로 해결됐다고 주장하지 않는다. 준비했던 추가 안전 여유 축소 설정도 아직 적용하지 않았다.
