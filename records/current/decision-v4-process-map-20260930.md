# V4 진행 규칙과 지도 설계 방향 (사용자 지시 2026-09-30)

사용자 원문:
> 앞으로는 나와 다 토론을 하고 결론을 다 내고 내가 수정하라고 지시할때만 수정하고 릴리즈할것.
> 내가 보는 방향과는 상관없이 내가 갈수있는(진행이 가능한 - 회전할때 시간이 걸리므로) MAP 으로 판단한다.
> 현재 적들을 2차원 MAP으로 만들어 놓는다, 우선은 내가 갈수 있는 길 위주로 탐색을 하지만, 지금처럼 내가 회전한 경우에는 이미 다른 영역의 map이 만들어져 있기 때문에 빠르게 출구를 찾을수 있도록한다.

규칙(사용자 결정): 코드 수정·빌드·릴리즈는 토론으로 결론을 낸 뒤 사용자가 "수정하라"고 지시할 때만 한다. 테스트는 사용자가 직접 한다.

설계 방향(사용자): (1) 판단 기준은 시야 방향이 아니라 회전 시간을 반영한 "도달 가능 지도". (2) 적·몸·벽을 2차원 지도(전 방향)로 항상 유지. (3) 탐색은 현재 진행 가능한 길 우선이되, 회전한 뒤에는 이미 만들어진 다른 영역 지도로 즉시 출구를 찾는다.

현재 V4 상태(빌드 0930-bd5a90bd, 사용자 1판 322초): 48px 격자 전 방향 지도는 있음. 첫 걸음만 ±100° 제한. 회전 시간은 미반영(격자 8방향 즉시 전환 가정). 적 머리는 현재 방향 원뿔의 시간 벽. 요동(틱마다 다른 출구) 확인됨. 수정은 사용자 지시 전까지 하지 않음.

## V4 재설계 합의 사항 (사용자 확인 2026-09-30, Codex 비판 검토 fact-v4-critical-review-20260930 반영, 코드 미수정)
1. 탐색 상태 = (위치, 방향, 속도). 8방향 격자 대신 실제 회전 원호(회전율 230→110°/s, 부스트 시 반경 2배)로 이웃을 전개. 방향 전환에 회전 시간이 들어감.
2. 경로 충돌 = 도착점만이 아니라 원호·선분 전체(몸·벽·적 도달 시간 벽) 검사.
3. 지도는 세계 좌표 고정 격자(우리 머리 중심이 아님)로 유지·갱신. 목표는 세계 좌표 셀로 유지, 도달 불가능해지거나 새 목표가 뚜렷이 나을 때만 교체(요동 억제).
4. 적 머리 시간 벽 = 현재 방향 직선이 아니라 t초 동안 회전 가능한 부채꼴(가까울수록 넓음).
5. 벽 근접 벌점은 도달 시각에 섞지 않고 별도 비용(시간 일관성 유지).
6. 명령 방향은 경로의 앞 지점(0.3초 앞)을 향하게 하고 추종층이 따라감.
미정: 적 속도 가정(현재 속도 / 상시 부스트). 실행은 사용자 "수정" 지시 후.

## 보완 3항 + 탐색기 (사용자 확정 2026-09-30)
7. 적 속도 = 현재 속도에서 즉시 가속, 0.57초(RAMP) 뒤 434px/s 도달하는 물리 모델(고정 0.3초 여유 대신). 미정 항목 해소.
8. 명령 지연 = 새 경로 시작 전, 측정된 지연(TRACK_LAT 계열, 현재 0.17~0.19초) 동안 현재 명령이 계속 실행되는 구간을 탐색 시작 상태에 포함.
9. 고정 지도의 몸·꼬리·머리 예측에 관측 시각과 만료 시간을 두어 오래된 장애물을 제거.
10. 탐색기 = 실제 회전 원호를 쓰는 상태격자 A*(위치·방향·속도), 일반 Dijkstra 아님.
상태: 설계 확정, 구현은 사용자 "수정" 지시 대기.
