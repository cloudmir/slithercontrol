# V10 알고리즘 적용 검토 — 구현 버그 우선 수정

사용자 지시: “땜빵으로 고칠 생각을 말고, 근본 알고리즘 적용이 맞는지 확인후, 버그성이면 고치고, 파라메터면 조정해. 그래도 구현이 안된 부분이다 할때 로직을 수정해.” 사용자의 개선 순서 선택이다. 쉽게 죽는다는 평가는 사용자 관찰로 구분한다.

원본 보존: research/v10_contract_audit_20261001/before/. 변경 ext/pilot.js, ext/mod.js 및 로컬 빌드 파일. 새 로컬 빌드1001-a21cb2ff. Windows 확장 재로드·배포·새 실게임은 하지 않았다. 기존 브라우저에 수정본이 적용되었다고 주장하지 않는다.

버그 재현·수정(변경 전 실패/후 통과인 회귀 검사5개):
1. 이미 전송된 명령의 지연 구간에서 충돌을 예측하면 진행 시간을 조기에 잘라 새 명령이 일찍 적용되는 것으로 계산함 → 지연 구간의 운동 예측은 끝까지 진행하고 충돌 플래그는 유지.
2. 긴 예측 구간에서 충돌 후보의 점수가 안전 후보보다 높아질 수 있음 → 안전 여부를 점수보다 우선. 현재0.6초 설정의 실제 사망 원인으로 입증된 것은 아님.
3. 예측 궤적의 충돌/종료 시간을 명령의 유효기간과 혼용 → 명령 유효기간과 궤적 종료 분리. 짧은 비상 계획도 동일한 명령 전달 경로 사용.
4. 명령 만료·오래된 응답에서 현재 머리 방향으로 덮어써 기존 회전을 취소 → 마지막 명령 목표각 유지, 부스트 해제. 이는 안전 보장이 아닌 갱신 공백 대응이다.
5. 개별 목표 탐색 시간 초과를 no_map_route로 보고할 수 있음 → budget 상태 보존. 탐색 성능 자체를 개선했다는 뜻은 아님.

검증: check.mjs 5/5 통과, 문법 검사 통과. 모의 브라우저3 Worker·만료 부스트 해제·모드전환·설정저장·페이지 오류0. 실제 tracker를 포함한 합성10시나리오에서 이전9/10, 수정10/10(서버 지연은 모의값). 기존 검증과 달리 추종기의 명령 취소 동작도 포함한다.

최근5판 마지막5초에서191프레임을 뽑아 명령 계약 재생: 신선 명령 즉시 만료14→0, 지연 구간 충돌 예측14→14. 기록된 거시 route는 블랙박스에 없어 재생에 포함하지 않았다. 따라서 실제 판을 살렸다는 반사실 증거가 아니다. 재생 실행시간은 Node VM 환경이며 실브라우저 성능으로 사용하지 않는다.

파라미터 실험: 근접H0.6/0.9/1.2 비교는 안전 후보 발견 프레임141/115/90. 긴 구간에서 안전 후보가 적어지는 결과만으로 생존 개선·악화를 판정할 수 없다. params.json·사용자 값 유지.

미구현 확인: 현재 v10Route는 위치 격자·직선 연결 기반 지도 가이드(geometryOnly=true, certified=false). 전 구간 회전반경·시간별 적 움직임을 만족하는 실행 가능한 장거리 탈출 경로 인증은 미구현이며 이번 버그 수정으로 완성되었다고 주장하지 않는다. 방향 흔들림·시간초과 자체·실게임 생존 개선도 해결됐다고 확정하지 않는다.
