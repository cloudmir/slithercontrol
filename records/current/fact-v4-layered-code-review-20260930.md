## 결론

Worker 분리와 계산 상한으로 이전 V4의 제어 정지 문제는 구조적으로 개선됐다. 그러나 아래 결함 때문에 현재 빌드를 실게임 성능 검증 기준으로 확정하기는 이르다.

1. **근접 회피의 반회전이 최대회전과 동일하다.** `v4Step`의 목표가 매 50ms마다 현재 방향 기준으로 다시 설정되어 `fr=±0.5`와 `fr=±1`이 완전히 같은 궤적이 된다(`ext/pilot.js:1172-1174`). 실제 함수 반례에서 0.9초 뒤 위치·방향이 양쪽 쌍마다 정확히 같았다. 후보 5개가 실질적으로 3개라 중간 회전 선택이 없다.
2. **몸 지도 기억이 부분 관측 때 사라진다.** 관측은 반경 안 선분만 수집하지만(`ext/mod.js:193-205`), 같은 뱀 ID가 다시 보이면 이전 폴리라인 전체를 현재 보이는 부분으로 교체한다(`ext/pilot.js:1055-1057`). 회전 뒤 다시 필요할 수 있는 기존 선분이 4초 만료 전에 즉시 유실된다.
3. **라벨 상한에서 안전 여유가 버려질 수 있다.** 비지배 라벨이 3개를 넘으면 비용 `g`만으로 정렬해 자른다(`ext/pilot.js:1114-1118`). 더 빠르거나 여유가 큰 비지배 경로가 제거될 수 있어 좁은 통로에서 위험하다.
4. **근접 선택은 명시한 사전식 순서가 아니다.** 적 도달 위반이 0인 후보 안에서도 여유·경로 거리·명령 유지·부스트 비용을 한 점수로 합친다(`ext/pilot.js:1183-1186`). 따라서 경로 추종과 성장의 우선순위가 보장되지 않는다.
5. **A/B 세계 모델이 C와 D에서 공유되지 않는다.** C Worker와 D Worker가 각각 별도 `Pilot`과 몸 기억을 만들며, C는 350ms 스냅샷만 받는다(`ext/mod.js:146-152,316-319`). 따라서 “공통 30Hz 세계 모델의 버전 스냅샷” 계약과 달리 두 층이 서로 다른 과거 지도를 사용할 수 있다. D의 1.2초 근접 재검사는 장거리 경로 불일치까지 검증하지 않는다.
6. **검증 수치 표기가 불일치한다.** 사용자 보고는 명령 요동 `529/1700`, 현재 설계 기록은 `5~29/1700`이다. 원시 산출물이 없어 어느 값도 확정할 수 없다. 4판 재생은 기능·속도 확인 범위이며 생존 개선 근거는 아니다.
