# Codex 리뷰 — pocket11/12, 실서버 사망 진단, 수정 방향 (2026-09-24)

사용자: "지금 codex 리뷰를 돌려봐, 지금 상황과 이전 수정방향도 맞는지 검증하고". 파일 수정·실사이트 실행 없음.

## 확인된 것
- 원 가장자리(rim) 몸 무시 진단과 pocket11 수정은 맞다.
  - pocket10 판: drawn 간격 −11.1px인데 coil_gap 6167.8px.
  - 인공 상황 검사: 기존 19,888px(무시) → pocket11 −8.1px(감지).
- 블랙박스 233357: 96개 후보가 모두 정적 여유 −90~−70px, 충돌 시간 0.033초로 동일했고, 탈출 명령이 좌우로 뒤집혔다.
- 블랙박스 233538: 첫 비상 탈출 때 몸까지 162.6px였다. 동기 계획층으로 재현해 원래 명령과 일치했다.
  - 위험 항을 하나씩 더하며 센 안전 후보 수: 몸·벽·현재 머리 24 → 직선 머리 예측 18 → +25t² 13 → +immediate(적 머리 472·243) **0**.
  - 즉 불확실한 적 머리 가정이 남은 후보를 모두 없앴다. cut 예측은 원인이 아니다.
- 유턴은 기하학적으로 가능했다(반경 57px, 0.944초). 반응하는 적까지 포함한 생존 증명은 아니다.

## 틀린 것
- pocket12(탈출 순위 변경)는 채택 불가.
  - 같은 6시드에서 pocket12 1/6 생존, pocket8·pocket11 6/6 생존.
  - `tc <= t0 → tc2`가 진짜 임박 충돌을 지운다. 반례: 초기 간격 +14.5px, 0.067초 뒤 충돌인데 무충돌로 바뀜.
  - obstacles()가 최대 12px을 다시 더하므로 "그림 굵기 그대로의 정확한 계산"이 아니다. 경로 샘플 사이 충돌 검사도 빠진다.
  - 머리·cut·벽 정보를 덮어쓴다.
  - HOLD(방향 유지 가점)는 경로 변위각과 이전 명령각을 비교해 실제 조향 유지가 아니다.
- 자체 검사 통과는 생존 개선 근거가 아니다(고정된 같은 상태만 반복함).

## 기록·실행 쪽 위험
- 블랙박스가 예외 종료 때 저장되지 않는다.
- 블랙박스가 선택한 명령만 담고 실제 적용된 명령과 구분하지 않는다. controller 내부 상태도 빠져 있다.
- full_view 표시가 누락돼, 계획층이 800px 관측도 전체 관측으로 받는다.
- live_batch.sh:
  - Esc로 끝난 판도 finished로 보고 다음 판을 시작한다.
  - stop 파일은 게임이 끝난 직후에만 확인한다.
  - 종료 코드를 직접 확인하지 않는다.
- live_staged 기본 스테이지가 회귀한 pocket12다.
- 시작 직후 'Execution context destroyed'는 1.5초 무명령 안전장치(watchdog)의 페이지 이동과 부합하지만 원인은 미확정이다. 첫 명령 전에는 안전장치가 작동하지 않는 구멍도 있다.

## 권장(리뷰어)
1. pocket11을 기준으로 유지한다. 다음 버전에서는 기록·batch를 먼저 정비한다(예외 저장, 적용 명령, full_view, 후보 탈락 원인).
2. 작은 비상 후보 집합(직진, 좌·우 최대 회전, 좌·우 유턴, 이전 행동 유지)을 만든다.
   - 새 충돌은 전 구간에서 보존한다.
   - 이미 겹친 장애물만 따로 식별한다.
   - 선택 순서: 몸 안전 후보 안에서 머리 위험 최소 → 동급이면 회전 방향 유지.
3. 새 충돌·기존 겹침·머리만 위험·유턴·rim 검사, 두 블랙박스, 같은 6시드와 별도 시드를 통과한 뒤 변경별 분리 실험을 하고 실서버에 올린다.
