# 새 알고리즘 제안 — 시간·방향을 포함한 다단계 경로 탐색

사용자 확인 전 설계안이며 구현·실험 성과가 아니다.

확인: 기존 active.py는 horizon=2.4, 미리 정한 첫 회전과 두 번째 회전 조합 및 원형 경로 등을 평가한다. 기존 v5 결과 파일은 보통 10판 생존율 0, 평균 생존 280.3867초이다. 이번에 시험을 재실행한 것은 아니다. 자동 자료 검색의 coverageStatus=missing이므로 전체 History를 전수 검증했다는 뜻이 아니다. 사망 원인별 기여율은 미확인이다.

제안: 기존 제어기·안전장치·학습 모델을 수정하거나 행동 결정에 호출하지 않는 독립 제어기를 작성한다. 물리 상수, 관측 인터페이스, 시뮬레이터 및 독립 평가 규칙은 재사용한다.

1. 위치·방향·시간을 상태로 둔 다단계 빔 탐색. 회전 한계, 몸 크기, 명령 지연, 부스트 소모를 반영하는 짧은 이동 조각을 연결한다. 매번 고정된 경로 목록을 채점하는 기존 구현을 재사용하지 않는다.
2. 상대 머리 이동과 새로 생기는 몸체를 예측하고, 경로 구간 전체의 충돌을 검사한다. 상대 예측의 불확실성을 명시한다. 관측 밖 미래나 월드 난수·상대 내부 목표를 제어기에 제공하지 않는다.
3. 끝점 이후 추가 탐색으로 탈출 경로와 선택 여유가 남는지 평가한다. 이는 유한 탐색에 의한 추정이며 무한 생존·모든 상대 행동에 대한 안전 증명이 아니다. 안전 후보가 없으면 예상 충돌이 늦은 비상 행동을 선택하고 실패 상태를 표시한다.
4. 생존 가능성 → 활동 구역 유지/복귀 → 순먹이 수집 순으로 선택한다. 긴급 일시 이탈은 허용하며 기존 활동 평가 기준을 바꾸지 않는다.
5. 독립 실행기·로컬 자동 플레이 뷰어를 새 파일로 제공한다. 기존 소스와 모델을 보존한다. 고정 회귀 장면에서 정면 교차·끼어들기·막다른 통로·포위·부스트·지연을 확인하고 계산시간도 측정한다.
6. 개발 시드와 최종 평가 시드를 분리하고, 동결 후 같은 미사용 시드에서 기존 v5와 새 제어기를 비교한다. 첫 사망 또는 600초 종료, 재생성 합산 금지. 보통 난이도 첫 평가 20판씩, 어려움 별도 5판씩. 환경 유효성, 활동 준수 완주율, 생존시간, 성장, 계산 지연, 신뢰구간을 보고한다. 기존 기준을 낮추거나 실패 시드를 제외하지 않는다. 18/20 성공은 관측 90%이지 실제 성공 확률 90% 입증이 아니다.

미해결: 새 탐색의 효과·계산 예산·장기 포위 대응은 구현 후 검증이 필요하다. 90% 목표 달성을 보장하지 않는다. 이번 설계로의 대규모 착수는 사용자 확인 대기. 실사이트 실행은 범위 밖이다.
