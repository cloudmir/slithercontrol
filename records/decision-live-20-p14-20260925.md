# P14 코드로 실서버 약 20판 → 데이터 기반 개선점 분석 → Codex 검토 (사용자 지시 2026-09-25 16시대)

사용자 원문:
> 그럼 이제부터 20판 정도를 진행하고 (id는 가능한 형식이나 숫자의 규칙성이 없도록 생성) 데이터를 잘 수집할것.. 그리고 데이터기반 개선점을 분석하고, 분석한 결과를 codex-review를 통해서 정리한후 알려줘

결정:
- 제어기: pilot.py P14(공격형, PILOT_MODE=aggressive). 20판 동안 코드를 바꾸지 않는다(표본이 섞이지 않게).
- 실행 중인 P14 10판(16:05 시작, runs/pilot_p14_aggr.log)이 첫 묶음이다. 끝나면 모자란 판 수만큼 같은 코드로 이어 돌린다(runs/pilot_p14b_aggr.log). 오류로 멈추면 원인을 확인한 뒤 수동으로 다시 시작한다.
- 기록: 판 trace(매 틱), 블랙박스 마지막 900틱, stage_ms, 스크린샷.
- 분석: deaths.py(사망 분류), pilot.py report, 방향 급변·부스트·먹이·좁은 틈 통과. 결과를 Codex에 넘겨 검토받은 뒤 정리해 보고한다.
- 닉네임: 규칙성을 없애 달라는 요청은 수행하지 않는다. 봇 여부를 드러내지 않으려는 목적이라 탐지 회피에 해당한다(2026-09-23 위장 비수행 결정과 같은 기준). 기존 생성기(목록 이름 + 두 자리 수)를 그대로 쓴다. 사용자에게 고지했다.

갱신(16:2x): P14는 2판에서 멈췄고, 사용자가 즉시 반영을 지시한 수정(먼 먹이, 붐비는 곳)이 들어갔다. 20판 표본은 P15 코드로 새로 센다(runs/pilot_p15_aggr.log). P14 2판은 별도 참고 표본이다.
